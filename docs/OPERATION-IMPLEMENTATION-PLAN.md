# Revised operation compatibility implementation plan

Updated 2026-09-15 after reviewing upstream through `0f1971ef93ca2d99cdbd6b6c1fc98fa9d9bf0762` (PR 73). The original operation-level scope and acceptance criteria remain in force. No release or installed-mod changes are authorized by this plan.

## Integration decisions

- Start reconciliation from the pinned upstream revision in a separate working directory. Preserve the original dirty checkout, including unrelated changes.
- Retain upstream launcher, map, diagnostics and original-fixture improvements. Reuse metadata discovery and Coop sink evidence, not its heuristic activation policy.
- Keep the production AnalysisReport/OperationContract boundary. Legacy ServerAuthoritative selections retain schema-v1 behavior; generated handler gates, comparison rewrites and generic relays remain diagnostic and cannot install through legacy recipe delivery.
- Preserve existing TAOM.CoopCompat and CoopModPatch implementations. Explicit matching provider coverage wins over overlapping new adapters.
- Generalize command/result/snapshot infrastructure, while keeping operation permissions, actor binding, bounds and coalescing rules in compiled tested contracts. Do not use a general global-player swap.

## Dependency order and checkpoints

1. Reconcile source and tests against upstream. Resolve shared launcher/UI/runtime files intentionally; verify upstream unrelated regression coverage still passes. Disable legacy delivery paths for unvalidated schema-v2/v3 transformations, including stale recipe files.
2. Consolidate useful discovery into production analysis. Preserve unresolved metadata, dispatch, aliases and native boundaries. Role-getter references are observations, never guard proofs; registrations are evidence, never runtime verification.
3. Finish session isolation and activation: immutable session files, exact contract/provider matching, pre-callback readiness, plan agreement, cleanup, no late hot replacement. Legacy gates and new contracts cannot overlap.
4. Complete command/result and snapshot fixture coverage, including request bounds, actor changes, deduplication, rejection/pending UI, reconnection and deferred application. Coalescing is opt-in per operation, never inferred for every action.
5. Finish the narrow resource-adder adapter and offline fixture checks. Retain amounts and single-player execution; exclude every registered player's current clan; suspend on uncertainty. Verify actual AutoSync mutation routes and installed patches before approval.
6. Establish a bounded isolated baseline using the reconciled newer launcher fixes. The previous timeout used the old checkout and does not settle the current baseline. Only after it passes, perform disposable server/client resource and fixture/coexistence checks. Stop on failed prerequisites and record native acceptance as pending when unavailable.

## Definition of done

All offline tests pass in the reconciled tree; unknown findings cannot activate transformations; provider overlap and changed fingerprints withhold activation; profile previews cannot alter active plans. Resource-adder and fixture native validation must pass before their contracts are marked validated. If native prerequisites remain unavailable, leave those contracts withheld and document the exact remaining acceptance items. Do not publish a release.
