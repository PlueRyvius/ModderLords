# Dedicated-server vanilla world generation

Verified locally on 2026-09-09: `vanilla_proof_20260909` and `vanilla_proof_20260909_repeat` were independently generated by the dedicated server, saved with exit 11, and loaded by separate processes to SERVING with exit 0. Both used the installed headless map scene (`A.G`) with 96 clans and 493 settlements. Their campaign IDs and hashes differ; each reload's input hash matches its preserved generated save.

The vanilla experiment uses a separate package and source build. It begins from commit `305a38e` plus the working-tree compatibility changes. Do not build the original checkout when its compat output is linked into the installed server.

## Reproduce

From the repository in PowerShell 7:

```powershell
pwsh -NoProfile -File tools/spike/Run-Vanilla.ps1 -Stage Setup
pwsh -NoProfile -File tools/spike/Run-Vanilla.ps1 -Stage All -Name vanilla_unique_name -NoBuild
```

`All` runs an ordinary template-backed loading control, two independent new-world creations and their separate-process reloads, another ordinary loading control, and a one-second creation timeout test. The template-backed controls do not count as generation. Each creation has a 900-second limit by default. Use a new name for every repetition.

The default sandbox is `D:\Design\Bannerlord Mods\_vanilla-world-proof`. Override `-Workspace`, `-InstalledServer`, `-EnginePort`, or `-JoinPort` as needed. Defaults are engine UDP 7299 and Coop UDP 4299. Each attempt uses a private password and disables Steam discovery. An occupied port causes failure; the harness never terminates its owner.

The setup copies actual stock files, excludes junctions, and builds the source copy with the Diagnostic configuration. The stock module set is Native, SandBoxCore, Sandbox, Coop, and DedicatedServer.Windows; world creation automatically adds DedicatedServer.ModderLordsCompat. TAOM is excluded.

## CLI contract

```text
launch --root PACKAGE --data-dir DATA --create-world NAME
       [--create-world-timeout SECONDS] [--world-log UNIQUE_LOG]
```

`--data-dir` isolates saves, config, logs, overlays, and (by default) `DATA\CoopData`. `--coop-data-dir` can override the latter. Diagnostic mode rejects `--profile` to avoid touching saved profiles. Normal defaults remain unchanged. Existing save names and `--create-world` with `--save` are rejected before launch preparation writes files.

The CLI automatically includes the required creation module and fails explicitly if its build cannot be found. Exit 11 means generation completed; 12 means creation failed or timed out; 2 denotes invalid launch arguments or preparation failure. Native crash codes remain distinct. Phase logs progress through armed, starting, campaign-created, map-ready, saving, and saved. A campaign-created line alone is insufficient.

For reload, the harness selects the exact generated name in the sandbox's `server-config.json` and launches with `--compat`. It intentionally avoids the official host's `/coopsave` mode, which forces port 4200 and bypasses the configured password. The underlying argument list is recorded in each attempt's `arguments.json`.

## Compatibility changes

The creation hooks run only in a dedicated process explicitly armed for world creation. They:

1. Wait for the host's normal container, save driver, native guards, and loading loop initialization. Intercept its `GameStateInterface.LoadGame(string)` call and invoke `StartNewGame()` instead. This retains the installed server's headless map-scene factory rather than entering the client map-scene path prematurely.
2. Use Coop's original-call scope during generation and initialize banner definitions before faction XML. Without early banner setup, the fresh campaign had no initialized clans and village production failed during map initialization.
3. Complete the standard character-creation finalization with a default Empire seed character, bypassing the intro video and interactive screens. Keep the host out of its serving phase while generating.
4. Save directly through `Game.Current.Save` with `AsyncFileSaveDriver`, as the host does. Its native autosave guard suppresses `SaveHandler.SetSaveArgs`, so queued `SaveHandler.SaveAs` never writes a file. Reuse engine metadata construction and repair empty headless version fields from Native's module version, matching the host's behavior.

Reflection targets validate their expected signatures and report unsupported APIs explicitly. Installed game and Coop binaries are not rewritten. Future server versions may require new compatibility work; these results concern the locally tested Bannerlord 1.4.8 / CoopNightly 0.1.5 package.

## Evidence and boundaries

Each attempt retains stdout, stderr, unique phase logs, arguments, elapsed time, and exit status under `runs`. Successful creations also preserve the original generated `.sav`, parsed header, and SHA-256 hash. Reloads record their input hash, so a later shutdown save cannot obscure which bytes were loaded. The harness rejects stale outputs, template-identical files, missing stock/Coop modules, premature serving during creation, and reloads that do not name the expected save and reach SERVING.

Cleanup applies only to the experiment's launcher and descendants, with a kill-on-close engine job. Both ports must be released afterward. The legacy spike harness also no longer terminates broadly matched server processes.

The local `RESULTS.md` in the experiment root records concrete results and artifact paths. Client joining, synchronization, long-running gameplay, TAOM generation, and launcher UI integration are outside this proof.
